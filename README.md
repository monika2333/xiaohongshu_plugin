# 薯页摘录

一个本地运行的 Chrome/Edge Manifest V3 插件。它会读取当前小红书或微博帖文，使用用户自行配置的文字与图片模型生成固定格式的中文舆情概括。接口采用 OpenAI-compatible `/chat/completions` 格式。

## 主要功能

- 支持小红书（`xiaohongshu.com/explore/…`）与微博（`weibo.com/<用户>/<微博>`）两种帖文页
- 提取作者、正文、页面日期、地点、点赞数、转发数（微博）、评论数和评论
- 小红书支持视频类帖文：读取平台自动生成的语音字幕作为口播内容，并按时间点截取画面帧交给图片模型识别；微博视频暂无字幕可读，尽力截取播放器当前帧
- 提取前 50 条一级评论及已经显示的回复（小红书按页面滚动顺序，微博按接口返回顺序分页拉取，支持长文自动展开与转发帖原微博并入）
- 使用可配置的图片模型逐图提取文字与关键视觉信息
- 小红书在评论区滚动加载时同步进行图片识别，待两类证据都就绪后再生成概括
- 使用可配置的文字模型综合正文、图片证据和评论观点
- 将“一天前”等页面相对时间按采集时的北京时间换算为绝对日期，并由程序统一写入结果（微博时间为官方绝对时间，按北京时间格式化）
- 启动任务前检查当前帖文页的登录会话（小红书 `web_session` / 微博 `SUB`）；未登录时直接提醒，不会开始采集
- 地点仍保留在采集数据中，但不会作为模型概括证据；无简报价值的普通配图会在文字概括前过滤
- 生成“一行星号标题 + 一整段正文 + 平台与完整页面链接”的固定格式
- 点击工具栏图标在浏览器右侧打开侧边栏面板（需要 Chrome 114+ / Edge 116+），面板常驻、不随页面点击消失
- 侧边栏提供“单条帖文概括 / 多条帖文概括”两个视图，截图上传在两个视图下均可用
- 可把最多 5 条帖文加入合并清单，支持小红书与微博混合添加，一次性生成跨帖跨平台统一简报（互动数求和、多链接由程序写入并逐条标注平台）
- 可上传已删除帖文的截图：单条视图下识别后直接生成一条概括，多条视图下作为一条帖文证据加入清单
- 可在概括完成后自动向飞书群机器人或指定飞书账号发送一条消息
- 一键复制与重新生成

## 安装与首次设置

1. 打开 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions`。
2. 开启“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择本项目文件夹。
4. 点击浏览器工具栏中的插件图标，打开右侧侧边栏面板，点击面板右上角“设置”。
5. 分别填写文字模型与图片模型的 API 地址、模型名称和 API Key。
6. 点击两个模型“测试”按钮确认连通；如需飞书推送，按下方说明填写并发送测试消息。
7. 保存设置。
8. 登录小红书或微博，打开一个帖文详情页，点击“提取并概括”。

推荐预设（所有字段都可以修改）：

- DeepSeek：`https://api.deepseek.com`，模型 `deepseek-v4-flash`
- Qwen：`https://dashscope.aliyuncs.com/compatible-mode/v1`，模型 `qwen3-vl-plus`

也可以改用其他提供 OpenAI-compatible Chat Completions 接口的模型。保存或测试时，浏览器会针对所填写的 HTTPS API 域名单独请求访问权限。

## 两种概括视图与截图识别

侧边栏顶部提供“单条帖文概括 / 多条帖文概括”两个视图（插件会记住上次使用的视图），概括结果与进度在两个视图下共用。

### 单条帖文概括

- 打开小红书或微博帖文详情页，点击“提取并概括”，生成单条简报。
- 下方“帖文截图概括”：原帖已删除、只剩截图时，上传截图（一次多张视为同一条帖文，可附原始链接），识别后直接生成一条概括，支持复制与重新生成。截图中的时间、互动数来自 OCR 抄录；相对时间（如“3天前”）无法换算时会在状态中提示并按截图兜底标注。

### 多条帖文概括

同一事件的多条帖文合并成一条简报，小红书与微博帖文可以混合加入：

1. 打开第一条帖文详情页（小红书或微博均可），点击“当前帖文加入清单”。插件会完整采集（含评论与图片识别）但不调用文字模型，采完后条目出现在清单里（清单徽标会标注“网页 / 微博 / 截图”）。
2. 依次打开其他帖文重复加入；清单最多 5 条，同一条帖文重复加入会替换旧采集。可随时移除或清空。
3. 本视图内也可“上传帖文截图”：截图识别后作为一条帖文证据加入清单，与网页帖文一起合并。
4. 点击“合并概括”，插件按发帖时间排序后把全部证据一次性交给文字模型，生成统一叙事的简报（跨平台时模型会按证据来源写明“小红书平台用户/微博平台用户”）；互动数为各帖求和，结尾拼接全部链接并逐条标注平台，均由程序写入。截图帖文若未填原始链接，结尾会标注原帖已删除。

清单和截图识别结果保存在浏览器会话存储中，关闭浏览器后清空；截图图片本身不会保存。

## 飞书自动推送

填写当前推送方式所需的配置后，每次概括或重新生成完成都会自动发送一条纯文本消息；未填写则不推送。推送失败只会显示错误状态，不会丢失已经生成的结果。

### 方式一：群机器人 Webhook（推荐）

1. 在飞书中创建或打开目标群，进入“设置 → 群机器人”。
2. 添加“自定义机器人”，复制飞书生成的完整 Webhook 地址。
3. 在插件设置的“飞书自动推送”中选择“群机器人 Webhook”，粘贴地址。
4. 如果机器人启用了签名校验，同时填写签名密钥。
5. 点击“发送测试消息”，确认目标群收到消息后保存；Webhook 留空即可停止推送。

Webhook 本身相当于发送凭据，请勿分享。飞书官方配置说明：[使用自定义机器人发送消息](https://open.feishu.cn/document/feishu-cards/quick-start/send-message-cards-with-custom-bot)。

### 方式二：自建应用私聊

1. 在飞书开放平台创建企业自建应用并添加机器人能力。
2. 申请“以应用的身份发消息”（`im:message:send_as_bot`）权限，创建并发布应用版本，并确保应用对接收人可用。
3. 从应用的“凭证与基础信息”复制 App ID 和 App Secret。
4. 填写接收人的飞书企业邮箱；也可以填写该应用下的 Open ID（`ou_…`）。
5. 点击“发送测试消息”，确认指定账号收到机器人私聊后保存；清空这三个字段即可停止推送。

自建应用方式先用 App ID 与 App Secret 获取 `tenant_access_token`，再调用飞书发送消息接口。官方说明：[机器人应用配置](https://open.feishu.cn/document/develop-an-echo-bot/faq)、[发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[获取 tenant_access_token](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)。

## 数据与密钥

- API Key、飞书 Webhook、签名密钥与 App Secret 默认使用 `chrome.storage.local` 仅保存在本机浏览器配置中，重启后无需重填；可以在设置页切换为关闭浏览器后自动清除的会话模式。
- 本机密钥存储被限制为仅插件可信页面和后台程序可访问，内容脚本无法直接读取；设置页提供一键清除密钥。
- 本机保存侧重个人设备上的使用便利，并非独立加密保险箱；能够控制浏览器配置文件的程序仍可能读取其中数据。尤其不要在多人共用或不受信任的浏览器配置中长期保存 App Secret。
- 非敏感模型配置使用 `chrome.storage.local` 保存。
- 本次采集数据、图片识别结果和概括结果仅进入浏览器会话缓存，插件不提供导出下载。
- 图片二进制不会写入缓存；需要识别时由扩展后台读取并临时转换为 Base64。
- 内容只发送给用户配置的文字与图片模型 API；填写飞书推送配置后，最终概括还会直接发送到飞书开放平台，不经过中转服务器。
- 用户上传的帖文截图会（压缩后）随识别提示词发送到所配置的图片模型 API；仅识别出的文本进入会话缓存，图片二进制不保存。
- 插件只读取小红书 `web_session` 与微博 `SUB` Cookie 是否存在，用于在任务启动前判断登录状态；不会保存、展示或传出 Cookie 值。微博帖文通过页面同源的 `/ajax/` 接口读取（与页面自身使用的数据接口一致）；小红书不调用未公开接口。

## 数据范围与容错

- 评论只取前 50 条一级评论，不代表全部评论。小红书为当前页面滚动顺序，微博为接口默认顺序（按热度）分页拉取；微博接口过滤部分评论时，实际可得条数可能少于页面标注的评论总数。
- 插件不会主动展开全部楼中楼，只附带已经显示的回复。
- 图片是平台当前提供的版本，不保证为创作者上传的未压缩原文件；单图最大处理 12 MB，单帖最多处理 18 张。
- 小红书视频帖使用平台自动生成的语音字幕（SRT）作为口播内容，字幕缺失或读取失败时只依据正文、评论与画面概括，并在结果中提示；画面截帧按视频时长取 6 个时间点，长边压缩到 720px。视频帖需要登录后才能读到视频流与字幕数据。微博视频帖暂无字幕可读，画面证据为播放器当前帧（尽力而为），两者都会在结果 uncertainties 中注明。
- 图片模型调用失败时会继续进行文字概括，并在结果中显示警告。
- “重新生成”会复用页面采集和图片识别缓存，只重新调用文字模型。
- 点赞数、评论数和采集时的完整页面链接由插件确定性写入，不交给模型自由生成，也不会根据帖文 ID 重新拼接链接。
- 微博帖文没有独立标题与公开收藏数，导出中相应字段显示为“无标题帖文 / 未显示”；转发帖会把“// @原微博：原文”并入正文一并提供给模型。

## 调整 Prompt

所有发送给文字模型和图片模型的提示词都集中在 `prompts.js`，包括：

- 图片模型 system Prompt
- 图片编号和批次返回要求
- 文字模型 system Prompt
- 证据 JSON 的 user Prompt 包装
- 模型连接测试 Prompt

直接编辑该文件即可调整提示词，不需要修改 AI 调用和数据处理代码。修改会影响模型输出的 Prompt 后，请同时更新文件顶部的 `VERSION`，这样插件会自动放弃旧 Prompt 对应的会话缓存。

图片模型返回字段和文字模型返回字段由 `ai-pipeline.js` 解析。如果修改 `summary_value`、`headline`、`event_summary` 等字段名，需要同步修改解析代码；仅修改写作规则、措辞、篇幅或取舍标准则不需要。

视频帖的页面状态读取由 `main-world.js`（注入页面主世界的桥接脚本）与 `content-script.js` 中的提取逻辑完成；截帧时间点、字幕长度上限等参数在 `content-script.js` 顶部的常量中调整。微博帖文的采集逻辑独立在 `weibo-content-script.js`，通过页面同源的 `/ajax/` 接口读取数据，采集上限（评论条数、页数、回复数）在同文件顶部的常量中调整。
