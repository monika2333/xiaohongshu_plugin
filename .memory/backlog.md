# 待办与已知问题

> 完成的条目从这里移除，并在对应任务记录里注明。新发现的问题随时加入。
> 优先级：高 / 中 / 低。

## 待办

### 链接概括的就绪等待上限是经验值（低）

v0.16.1 给小红书采集端加了 bounded 等待：互动数/评论总数出现才继续（上限约 6 秒），评论区挂载与首条评论各等最多约 10 秒。若实际网络下页面挂载或评论接口超过上限，评论仍会缺失，此时 `uncertainties` 会注明「评论未能读取」而不是静默。触发条件：实际使用中链接概括仍出现无评论、无互动数的简报，届时调大 `content-script.js` 的 `TIMING`。

### 延迟推送完成前面板被关闭时自动推送会丢失（低）

v0.16.0 中，后台把推送标记为 `deferred` 后要等面板补完链接再补发；如果用户在这之前关闭侧边栏，这次自动推送不会发生。历史与工作流快照保留 `deferred`，用户之后可在结果/历史里点飞书图标手动发送。若要自动补，需要后台持久化待发文本并在面板下次打开时补发，收益有限，暂不做。

### 合并运行中条目集合变化时不并入新链接（低）

合并期间清单条目被增删后，`itemIds` 已变，后台拒绝原地重渲染；v0.16.0 会保留原结果、推送原文本，并在「添加素材」提示“合并条目已变化，本次合并结果未包含新的链接。”。如需把新链接并入，需要重新发起一次合并（会再次调用文字模型），不在本次范围。

### 旧数据的 notification 缺少 sentText（低）

v0.16.0 之前的历史/工作流结果没有 `notification.sentText`，无法判断飞书里是否为旧版本，界面按“无法判断”不显示标记。如果希望旧结果也能标旧版本，需要一次性迁移或在首次手动发送时补写；当前保持不报错的兼容处理。

### 截图识别的剩余改进项（低）

v0.15.0 已解决截图概括对齐单帖的主要根源（配图文字裸原文进证据、相对时间被丢弃、上传前压缩毁字）。剩余可选项，触发条件是实际使用中仍出现识别不清、被接口拒收或写法偏差：

- 截图识别是一次调用同时完成 OCR 抄录、拼接去重和结构化输出，负担重。可以考虑拆成「逐图忠实抄录」和「再整理」两步。
- `SCREENSHOT_SYSTEM` 和 `buildScreenshotPayload` 把平台写死为小红书，微博截图会被标错平台。

### 长截图自动切段（低，待触发）

v0.15.0 已改为截图原样上传，先观察模型对长截图的处理。高度超过宽度约 2.5 倍时，按原分辨率切成有重叠的几段，复用截图提示词的「拼接去重」规则。触发条件：实际使用中长截图识别不清或被接口拒收。

### 概括格式重构（待讨论）

用户设想过「用户自定义模板 + 程序填日期/互动/链接变量」的格式重构，涉及 JSON 字段结构与渲染方式，后续单独讨论，本次（v0.15.0）未动。

### 任务进行中清空链接需等任务完成（低）

补链接可以暂存到任务完成后应用；清空链接目前会提示“任务进行中，完成后才能清空”，不会延迟执行。如需支持，增加 pending 清空状态并在任务完成检查里处理。

### 清单条目补链接提示偏长（低）

清单条目命中补链接时，提示仍带条目标题，长标题下提示偏长；单条帖文场景已在 v0.13.7 收敛，可考虑同样截断。

### 可选：zh_CN 本地化（低）

需要在 manifest 里设置 `default_locale`，使用 `__MSG_extName__` 占位，并新建 `_locales/zh_CN/messages.json`。

## 已知限制（接受，暂不处理）

- 微博链接路径为纯数字 mid 时无法与 mblogid 匹配，按「无法解析」处理，交由用户手动选择。
- 短链在触发风控时会落到什么页面尚未实测。登录状态不影响解析，因为后台请求不携带登录信息。
- 不支持旧分享域名 `xhslink.com`。
