# v0.21.2 修窄窗口上下排列时评论只加载一页、评论区长截图全黑

- 日期：2026-11-19
- 版本：manifest / package.json 均为 0.21.2
- 提交：见本次提交
- 委托：用户把浏览器窗口调窄后，小红书帖文从左右两栏变成上下排列；此时「提取并概括」能生成概括，帖文初始屏正常，但评论区长截图是一整张黑图。
- 关闭的 backlog 条目：无

## 原因

用户那次的存档里：评论区长截图 1396×5439 像素全为 0（画布上什么都没画）；采集数据里评论只取到 10 条（页面显示共 64 条），停止原因 `page_exhausted`。

窄窗口下 `.note-scroller` 不再自己滚动（高度随内容撑开），真正在滚的是外层弹层或页面。于是：

- 采集脚本只滚 `.note-scroller`，滚不动，以为到底了，评论停在第一页的 10 条。概括能生成，所以用户以为评论正常。
- 截图测出来的「截取区域」就是整个 `.note-scroller`，比屏幕还高，被当成一屏；拼接时去画面外取像素，什么也画不上，得到全黑的图。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `content-script.js` | 新增 `resolveCommentScroller`：从 `.note-scroller` 往上找第一个设了滚动且内容超出的元素；都没有时，帖文不在固定定位的弹层里就用页面；再不然退回第一个设了滚动的。`loadTopLevelComments` 滚它。 |
| `archive.js` | 页面函数（`pageMeasure`、`pageScrollPosition`、`pageRestoreScroll`、`xhsCommentRange`）内置同一规则的 `resolveXhs` 与 `xhsFrame`：截取区域横向取帖文那一栏、纵向取滚动区域在屏幕上看得见的部分；返回的 `scrollTop` 统一为「截取区域上沿对应的内容坐标」；弹层自带的顶栏底栏不在滚动容器里，用 `elementFromPoint` 命中测试计入遮挡。`composeLong` 发现截取位置超出画面直接报错，不再拼出空白图。 |
| `tests/content-script.test.cjs` | 窄窗口：滚外层弹层才能加载出更多评论，结束后外层恢复原位、`.note-scroller` 不动。 |
| `tests/archive.test.cjs` | 窄窗口测量：滚外层、截取区域为帖文那一栏的可见部分、顶栏 56px 计入遮挡、锚点与评论区范围按外层坐标；宽窗口照旧截 `.note-scroller`；截取位置超出画面时报错。 |
| `tests/service-worker.test.cjs` | 版本断言 0.21.2。 |
| `README.md` | 数据范围一节注明窄窗口也能正常加载评论与截图。 |
