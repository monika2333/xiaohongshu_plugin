# v0.16.2 面板跟随页签内跳转，修「提取并概括」一直置灰

- 日期：2026-11-15
- 版本：manifest / package.json 均为 0.16.2
- 提交：见本次提交
- 委托：用户口头排查「概括完上一条之后，再点『提取并概括』按钮一直是灰色、点不了；刷新网页也没用；插件是从 Edge 商店装的，代码与仓库一致」。
- 关闭的 backlog 条目：无

## 根因

面板把「当前页签是不是帖文页」缓存在 `activeTabUrl` 里，`refreshButtons()` 用它算 `postPage`（`panel.js`）。这个缓存只在三处更新：面板打开时的 `getActiveTab()`、`chrome.tabs.onActivated`（切页签）、`chrome.windows.onFocusChanged`（窗口焦点变化）；另外只有真正点下按钮后 `prepareCurrentPage()` 才重读一次。

面板没有监听 `chrome.tabs.onUpdated`，因此同一页签内的地址变化——从首页/搜索点开笔记这类前端跳转、刷新、前进后退、分享链接落地后手动点进笔记——都不会更新它。缓存停在一个非帖文地址（例如 `xiaohongshu.com/explore?...` 分享落地页）时，`postPage` 恒为 false，`提取并概括` 与 `加入清单` 一直置灰；F5 不触发上述三个事件，所以刷新网页没用；切页签会触发 `onActivated`，所以能救回来。

现场核对（Edge 已运行时用 UI Automation 读侧边栏控件）：两个按钮 `enabled=False`，按钮文案仍是「提取并概括」而非「正在处理…」，状态卡是默认的「准备就绪 / 请先打开帖文详情页。」，而浏览器当前页签其实是 `/explore/<24 位 id>` 帖文页；切到另一个页签再切回来，按钮立刻恢复。说明不是任务卡住，也不是采集或模型的问题，纯粹是按钮门控用了过期地址。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `panel.js` | 新增 `syncActiveTabUrl()`：用 `chrome.tabs.get(activeTabId)` 重读活动页签，地址变了就更新 `activeTabUrl` 并重渲染按钮；带了「仍停在同一篇帖文（例如地址补了 `xsec_token`）就保留旧结果，换了帖子或离开帖文页则清槽位」的判断，且页签任务进行中不清槽位。新增 `chrome.tabs.onUpdated` 监听（只处理活动页签的 `url` 变化与 `status=complete`）和 `document` 的 `visibilitychange` 监听（侧边栏重新展开时补一次）。`getActiveTab()` 在 `currentWindow` 查不到活动页签时退回 `lastFocusedWindow`，避免 Edge 侧边栏里 `currentWindow` 解析不到浏览器窗口时面板以为没有活动页签。 |
| `tests/panel.test.cjs` | mock 补 `tabs.onUpdated`；断言必须注册该监听。新增三个用例：① 首页（非帖文页）置灰 → 页签内跳到帖文页（只发 `onUpdated`）后按钮恢复可用、显示「小红书」徽标；② 完成概括后在页签内回到首页 → 按钮置灰、旧页面的结果卡收起；③ 刷新（同地址、只发 `status=complete`）不清掉当前结果、按钮保持可用。 |
| `tests/service-worker.test.cjs` | 版本断言 0.16.1 → 0.16.2。 |
| `README.md` | 「当前帖文」条目补一句：页签内的跳转也跟随（首页点开笔记、刷新、前进后退都重新判断地址）。 |
| `manifest.json` / `package.json` | 版本 0.16.2。 |
| `.memory/context.md` | 版本号与「关键约定」补一条页签地址跟随的说明。 |

## 实测与验证

- `npm run check`：通过（语法检查 + 9 个测试脚本 + 打包白名单防漏）。
- 新增用例的防漏验证：把 `panel.js` 临时换成上一版（HEAD）跑 `tests/panel.test.cjs`，因缺少 `chrome.tabs.onUpdated` 注册而失败；换回后全部通过。
- 需要在真实浏览器里手动验证的步骤：
  1. 在小红书首页点开一篇笔记（同一页签内跳转），侧边栏「提取并概括」应直接可用，不需要切页签。
  2. 在帖文页按 F5 刷新：按钮仍可用；已显示的结果不会被清掉。
  3. 从帖文页点回首页/其他页面：两个按钮应置灰，旧结果卡收起（概括正文仍在历史里）。
  4. 正常切页签、切窗口、关闭页签：行为不变。

## 偏离委托的地方

无。委托只要求排查，修复范围由本次按「按钮门控用过期地址」这一根因收敛，没有改动采集、模型与飞书链路。

## 遗留问题

无。新发现的两点不需要单独跟进：`currentWindow` 的兜底属于防御性改动，未在 Edge 侧边栏复现到具体失败；页签内切到**另一篇**帖文时旧结果会被清掉（与切页签语义一致），历史仍保留。

## 审核备注（仅当新增权限或数据流时）

无新增权限、host_permissions、网络域名或数据外发；只改变面板读取当前页签地址的时机。
