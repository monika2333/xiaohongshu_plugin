# v0.16.4 涉事主体规则补「数字回复=选项序号」，链接编辑器不再吞全角括号

- 日期：2026-11-15
- 版本：manifest / package.json 均为 0.16.4
- 提交：见本次提交
- 委托：用户实测 v0.16.3 后，同一条「北京某高校洗澡水发黄」帖文仍写成「发帖人仅回复‘定位附近的某学校’，未公开学校名称」；用户提供实验用 DeepSeek Key，请实现方自己复现、调整。
- 关闭的 backlog 条目：无

## 排查

- 用内置浏览器打开原帖（未登录），按 `content-script.js` 的选择器（`.parent-comment` → `.reply-container .comment-item-sub`、作者 `.tag`）在页面上跑了一遍：「航天桥，你是北工商还是首师的啊」下挂发帖人回复「1」，`isAuthor` 为 true。证据不缺，问题仍在提示词。
- 本地按真实评论还原 payload，经 `XhsAi.buildEvidence` + `TEXT_SYSTEM` 直接调 deepseek-chat（temperature 0.2，与线上一致）复现：v0.16.3 规则下模型看到了追问，但把「1」理解为「未明确确认」，标题仍写「某高校」。原因是 v0.16.3 的措辞「简短回复可能就是在确认」太弱，也没说数字回复怎么读。
- 实验脚本放在会话临时目录，没有进仓库；Key 只通过环境变量传入，没有写进任何文件。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `prompts.js` | `SUBJECT_RULE` 改写：明确发帖人评论区回复是本人说法；回复「对」「是」即确认网民所说；网民追问列出选项时，回复数字表示选中对应序号的选项。确认后正文简要交代「发帖人在评论区确认」、不复述推断过程，已确认的猜测不再写入 opinion_points。分级规则（仅网民猜测时保留代称）不变。 |
| `panel.js` | `saveLinkEditor` 先经 `extractPostUrl` 提取链接再校验。用户这次的结果链接尾部是 `%EF%BC%89`：在结果卡 ✎ 行内编辑里粘入「（小红书 https://…）」整段时，旧代码直接 `new URL`，把黏尾的全角「）」编码进了链接。素材输入框本来就走 `extractPostUrl`，现在两边一致。 |
| `tests/prompt-overrides.test.cjs` | 断言改为新措辞的关键要求（数字回复、确认依据、全称）。 |
| `tests/panel.test.cjs` | 新增：网页帖与截图帖的链接编辑器粘入带全角括号的整段文字，只保存干净链接。 |
| `tests/service-worker.test.cjs` | 版本断言升到 0.16.4。 |

## 实测与验证

- `npm run check`：通过。
- DeepSeek（deepseek-chat）实测，还原证据：
  - 有「1」回复：10/10 次标题为「网民反映北京工商大学学生洗澡水发黄浑浊」，正文写「发帖人在评论区确认涉事学校为北京工商大学」；1/6 次观点里仍多出一条「部分网民猜测为北工商或首师」。
  - 去掉「1」回复：3/3 次标题保留「某高校」，观点里写明网民猜测的北京工商大学或首都师范大学。
- 需要用户手动验证：重新加载扩展后对原帖「重新生成」；设置页若自定义过单帖概括提示词，需「恢复默认」。合并提示词共用同一规则，但只测了单帖。

## 遗留问题

- 规则里写了「标题和正文从一开始就用全称、不再出现代称」，实测模型正文仍先写「北京某高校……」，再写「发帖人在评论区确认为北京工商大学」。读起来通顺、也更贴近原帖，所以没再硬压；若用户希望正文第一句就写全称，再调这半句。
- 偶发（约 1/6）观点区重复「网民猜测为……」，暂不处理。
