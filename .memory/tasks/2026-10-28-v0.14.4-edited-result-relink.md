## 实测与验证

- `npm run check`：通过（含新白名单测试；输出 `package whitelist covers 17 runtime references`）。
- 白名单防漏验证：临时从 `scripts/package.ps1` 删掉 `"panel.js"`，`node tests/package.test.cjs` 以 `白名单漏掉了运行时文件：panel.js` 失败；随后恢复并重新跑通。
- 单元测试覆盖：编辑过正文后补链接保留正文、只换后缀；后缀删除后按旧链接替换；两者都找不到时 `kept`；截图后缀两种形态互切；合并结果只改对应链接；历史文本不含手工编辑；换链接过程没有任何网络请求（测试里的 `fetch` 会直接抛错）。
- 需在真实浏览器侧边栏确认：
  1. 改过结果正文后，在“添加素材”贴同帖短链，正文不变、末尾换成短链。
  2. 编辑截图结果后补链接、再清空，后缀在“（小红书 链接）”与“（原帖已删除……）”之间切换。
  3. 编辑时删掉末尾链接段再补链接，正文不变并出现“未能自动替换”提示；清单与 payload 里的链接已更新。
  4. 编辑合并结果后改清单条目链接，只替换合并后缀中对应的链接。
  5. 任务完成后自动应用暂存链接时，同样保留编辑；历史里的文本仍是干净版本。

## 偏离委托的地方

1. 合并结果的旧后缀/旧链接由 `setMergeItemLink` 在更新清单前算好并随响应返回，没有把整组旧 payload 复制进结果对象。效果等同于“用旧 payload 算旧后缀”，避免结果对象和历史被大块 payload 撑大。
2. 补链接后的提示统一显示在“添加素材”区块的 `link-feedback` 信息条；没有新增结果卡片内的提示元素。`kept` 使用 `data-state="info"` 的绿色提示态。
