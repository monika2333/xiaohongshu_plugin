- 日期：2026-11-19
- 版本：manifest / package.json 均为 0.21.0（在独立分支上开发时曾编为 0.18.0 / 0.18.1，与 master 同期的 0.18–0.20 撞号，并入 master 时合成一个版本）

## 用户确认的细节

- 必须是原始画面，不接受程序按采集数据重新排版的「存档图」；也不调用其他截图插件。
- 只截两张：帖文初始屏（不滚动的整屏）+ 评论区长截图（逐屏截取后拼接）。帖文配图另存原图文件。
- 存放位置：设置页选任意文件夹（File System Access），不用下载目录子文件夹。
- 开关默认关闭，开启时申请可选的「所有网站」权限；开启后要提醒用户截图期间不能切换页签。
- 只为有概括记录的帖文写入：加入合并的帖文等合并概括完成后才写入，从合并概括里移出或清空就丢弃（没合并说明不重要）；概括失败的先留在内存，重新生成成功后写入。
- 微博评论区长截图最多 10 屏（最初定 15 屏，用户认为偏多）。
- 删除单条 / 清空历史时一并删除对应存档；历史超 100 条自动淘汰时存档保留。

## 技术验证（2026-11-19，临时扩展，未入库）

- Edge 157 在没有 `<all_urls>` 时截当前页签报 `Either the '<all_urls>' or 'activeTab' permission is required.`：现有权限（含 `activeTab`、`https://*/*`）不够，侧边栏打开不授予 activeTab，链接新开的页签更没有。
- Chrome 157 授权 `<all_urls>` 后：当前页、链接新开页、小红书初始屏 + 评论区长截图、微博长截图均成功，用户目测拼接无缝、无重复；选文件夹、写文件、按名删除文件夹均正常。
- 微博评论区 DOM：评论 tab 为 `.wbpro-tab3`，正文为 `article`，两者共同祖先是正文那一栏（宽约 642px）；顶部 60px 固定导航 + 正文栏顶部 46px 吸顶「返回」条；评论列表是 `vue-recycle-scroller`（page-mode 虚拟列表，滚到才渲染）。CSS 类名带哈希，只用这两个稳定选择器。

## 实测与验证

- `npm run check`：通过（含新增 `tests/archive.test.cjs`）。
- 正式代码尚未在真实浏览器里跑过，需要用户手动验证：
  1. 重新加载扩展，设置页打开「截图存档」应弹出「访问所有网站」授权；拒绝则开关回到关闭。选择一个空文件夹。
  2. 小红书帖文点「提取并概括」：侧边栏顶部出现红色提示条，评论区逐屏滚动；完成后结果卡显示「已保存到…共 N 个文件」，文件夹里有初始屏、评论区长截图、配图、采集数据、概括。
  3. 截图过程中切到别的页签：应立即停止并提示，结果卡出现「重新截图」，回到帖文点它能补截。
  4. 微博详情页、链接新开页签、「＋ 加入合并」后合并概括（合并前文件夹里不应出现、移出的那条不出现）、截图识别（含自动切段的长截图，存档里应是原图）各试一次。
  5. 历史屏删除这条记录：提示会删 1 个存档文件夹，确认后文件夹消失；清空历史同理。
  6. 浏览器重启后再提取：应弹一次文件夹「允许」，或结果卡出现「授权文件夹并保存」。

## 偏离委托的地方

- 评论区长截图在小红书截到第 50 条一级评论为止（与采集上限一致）；微博评论区随滚动无限加载，按 10 屏封顶，并在存档状态里注明「只截取了前 10 屏」。
- 「只为有概括记录的帖文写入」同样用于概括失败（最初方案是失败照样存档）。失败后结果卡不显示，用户多半会重新点「提取并概括」，这会重新采集并生成新存档，失败那次的截图被丢弃。

## 审核备注（新增可选权限与本地文件写入）

本版本新增可选功能「截图存档」，默认关闭。用户在设置页主动开启时，扩展才通过 chrome.permissions.request 申请可选主机权限 <all_urls>：Chrome/Edge 的 chrome.tabs.captureVisibleTab 截屏接口只接受 <all_urls> 或 activeTab，而 activeTab 不适用于侧边栏发起的操作和扩展新开的页签。扩展只在用户点击「提取并概括」等按钮、且该帖文页签处于前台时截取页面画面（帖文初始屏与评论区），每次截屏前后都会确认页签未被切换，不会截取其他页面，也不会在后台运行。截图、帖文配图、采集数据与概括文本只通过 File System Access API 写入用户自己选择的本地文件夹，不上传到任何服务器；用户删除概括历史时扩展会一并删除对应存档文件夹。安装时的权限没有变化，不开启存档的用户不会看到新的权限请求。

This version adds an optional, off-by-default "screenshot archive" feature. Only when the user turns it on in the options page does the extension call chrome.permissions.request for the optional host permission <all_urls>, because chrome.tabs.captureVisibleTab only accepts <all_urls> or activeTab, and activeTab is not granted for side-panel actions or extension-opened tabs. Screenshots are taken only of the post tab the user is processing, only while that tab is in the foreground (checked before and after every capture), and only after the user clicks a summarize button. Screenshots, post images, captured data and the summary are written solely to a local folder the user picks via the File System Access API; nothing is uploaded. Deleting a history entry also deletes its archive folder. Install-time permissions are unchanged.
