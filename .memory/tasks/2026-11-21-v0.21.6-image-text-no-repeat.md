# v0.21.6 单帖概括不再把与标题意思相同的图片文字再说一遍

- 日期：2026-11-21
- 版本：manifest / package.json 均为 0.21.6
- 提交：见本次提交
- 委托：用户装上 v0.21.5 实测北理国补帖，标题已认出北京理工大学，但正文在「北京理工大学10月的国补和校补未到账银行卡」之后又跟半句「所附文字同样在问“北理补发的国补和校补啥时候到账银行卡呢”」，前面已讲清，认为没必要；请修正提示词。
- 关闭的 backlog 条目：「文字模型偶尔把配图文字原样引用」（v0.21.5 新增）

## 原因

`prompts.js` 单帖 `TEXT_SYSTEM` 的图片规则开头是「图片证据是正文的补充」，只点名禁止「配图为……」「图片显示……」两种说法。模型因此把图片当成标题之外的第二个信息源，意思相同也要另起半句交代（「所附文字同样在问」「其发布的图文卡片中同样……」「帖文以文字图片提出……」），换个说法就绕过了两条禁用词。第 3 条「重复信息只写一次」压不住这一点。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `prompts.js` | 只改 `TEXT_SYSTEM` 的图片规则一句：图片证据和标题、正文同属这一条帖文，不是另一个信息源；只把多出来的信息（如具体名称、事项）并入对同一件事的陈述，意思相同的部分不再复述，也不交代哪些内容出自图片。原有「配图为……」「图片显示……」与「不描写外貌、服饰……」保留。合并提示词 `MERGE_SYSTEM` 未改。 |
| `tests/service-worker.test.cjs` | 断言新规则在、旧说法「图片证据是正文的补充」不在；版本断言改为 0.21.6。 |
| `manifest.json` / `package.json` | 版本 0.21.6。 |

缓存键含生效提示词哈希，旧的文字概括缓存自动失效；用户在设置页自定义过「单帖概括」提示词的不受本次影响。

## 实测与验证

- `npm run check`：通过。
- DeepSeek `deepseek-flash` 实测，图片识别结果固定为实测得到的 `supporting` 版（含「图文卡片」画面描述与「图片文字以提问方式称」的主张），评论按页面前 7 条构造，只调文字模型，正文命中「图文 / 所附 / 配图 / 图片 / 图中 / 卡片 / 帖中文字 / 原句」即算复述：
  - 修改前：12 次中 5 次（另 1 次「以图文提问方式询问」，算上为 6 次）。
  - 修改后：两批共 24 次中 1 次（「图片文字中追问……」）；标题 24/24 写出「北京理工大学」，没有因为「只并入多出来的信息」丢掉学校名称或国补、校补。
- 回归：图片是通知、承载主要内容的帖（标题「学校这通知啥意思啊」，图片为宿舍断电与门禁通知），修改后 5/5 次正文完整转述 22:30 断电、23:00 门禁等要点，没有因「不再复述」把通知内容略掉。
- 需要用户在浏览器里验证：重新加载扩展后对北理国补帖点「重新生成」，正文不再出现「所附文字同样在问……」。
