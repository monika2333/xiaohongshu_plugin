# v0.16.3 概括提示词：从评论区线索查明涉事学校、单位全称

- 日期：2026-11-15
- 版本：manifest / package.json 均为 0.16.3
- 提交：见本次提交
- 委托：用户反馈一条「北京某高校洗澡水发黄」的概括写成「发帖人未说明学校全称」，但评论区有网民追问「航天桥你是北工商还是首师的」，下面回复「1」，实际可推断为北京工商大学。要求：能从评论区推断出具体学校、或帖文只写了简称时，都要尽量推断出具体学校。
- 关闭的 backlog 条目：无

## 原因

证据本身不缺：`compactComment` 已把一级评论下已显示的回复（含 `isAuthor` 标识）挂在被回复的评论下交给文字模型。问题在提示词：
- 只有单帖 headline 规则里一句「学校名称须写全称」，没有要求「名称没写明时去查」；合并提示词连这句都没有。
- event_summary「只依据帖文本身」、全局「不虚构主体」「评论中的推测写成部分网民猜测」，模型因此选择最保守的写法，把发帖人的「1」也当成无法使用的信息。
- opinion_points「不列举具体例子、个案」让模型只写「列举校名」而不写出校名。

## 实测与验证

- `npm run check`：通过。
- 需要用户在浏览器里手动验证：对原帖点「重新生成」，确认标题写成「北京工商大学」、正文交代发帖人在评论区确认。注意：如果设置页「概括提示词」里**单帖概括**已自定义，内置规则不会生效，需要点「恢复默认」或把这条规则手动并入。

## 偏离委托的地方

- 委托只说“尽量推断”，分级处理由实现方提出、用户随后确认：发帖人确认或证据充分才在标题正文写全称；只有网民猜测时保留「某高校」，猜测对象写进网民观点。已记入 `decisions.md`。
