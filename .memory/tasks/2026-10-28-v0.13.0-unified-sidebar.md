## 实测与验证

- `npm run check`：通过。
- 短链实测（未登录、匿名网络）：`xhslink.cn/o/<短码>` 经 302 跳到 `www.xiaohongshu.com/login?redirectPath=…`，帖子 ID 只出现在 `redirectPath` 参数里，页面没有 `og:url` 和 canonical。后台请求固定不携带登录信息，因此浏览器是否登录不影响跳转形态。风控页尚未遇到。
- 用户确认：新界面排版可用。

## 偏离委托的地方

1. 清单的链接编辑器是单个共享控件，编辑时移动到对应条目下方，视觉上等同于原地编辑。
2. 微博纯数字 mid 链接一律按「无法解析」处理，避免误报为「指向另一条帖文」。
3. 实时结果卡片仍不显示「打开原帖」按钮，保持原有行为。
4. 旧版本会话里残留的截图 payload，如果链接写在 `source.url` 中，清空链接后会回退到该地址，而不是「原帖已删除」。扩展更新会清空会话存储，正常升级不会遇到。
5. 只支持 `xhslink.cn`（用户确认，见 `decisions.md`）。
6. 通过链接打开微博帖文时，改为检查微博的 `SUB` Cookie，而不是小红书的。
7. 合并结果严格按焦点规则处理：切走页签后不再显示。这一点被验收判定为问题，由 0.13.1 修复。

## 遗留问题

验收发现以下问题，已列入 `backlog.md` 的「0.13.1 修复」：

- `DELIVERY.md` 放在根目录，会被打进扩展包。

## 审核备注（新增 xhslink.cn 权限）

> 本扩展新增 `https://xhslink.cn/*` 主机权限，仅用于解析用户主动粘贴的小红书分享短链。用户粘贴短链后，扩展后台会向 xhslink.cn 发起一次不携带登录信息的请求，跟随跳转后只读取最终地址、地址中的跳转参数，以及落地页的 `og:url` / `canonical` 元信息，以确定该短链对应哪条小红书帖子，并把链接补到用户已有的概括素材上。该请求不读取、不保存页面正文，不上传任何数据，也不会在后台自动发起；用户不粘贴短链时，扩展不会访问 xhslink.cn。
