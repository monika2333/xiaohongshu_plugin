# v0.17.0 设置页模型默认共用一组，按需再分开配置文字与图片

- 日期：2026-11-15
- 版本：manifest / package.json 均为 0.17.0
- 提交：见本次提交
- 委托：设置页原本要分别填文字概括模型和图片识别模型。用户希望默认只填一次（默认 deepseek-flash，只需填一个 API Key），模型不同时支持文字和图片、或有自定义需求时才分开填。方案先讨论、经用户确认后实现。
- 关闭的 backlog 条目：无

## 用户确认的细节

- 分开模式下图片 Key 留空：两边 API 同域名时沿用文字 Key，不同域名必须单独填。
- 测试模型时多发一张内置小图，确认模型能看图。
- 共用模式报错文案说「模型」，分开模式保留「文字模型 / 图片模型」。
- 旧配置迁移：不存在「填了文字 Key、图片 Key 留空」的老用户，不用为这种情况设计。

## 实测与验证

- `npm run check`：通过。
- 设置页布局：用内联样式的副本在内置浏览器里按 1280 宽测了元素位置（共用 / 分开 / 切换按钮三种状态），字段、测试行、开关、图片组纵向排列，无横向溢出。修了一处：`.card-actions` 原有 `grid-column: 3`，放进组内会撑出隐式列，已在 `.model-group .card-actions` 复位。截图因应用窗口隐藏未能拍到。
- 追加修正（同版本）：窄屏（< 820px）媒体查询给 `.fields` 设了 `grid-column: 2`，模型组里的字段被挤到右半边；`.model-group .fields` 与 `.card-actions` 一并复位，`tests/options.test.cjs` 加了样式断言。用户反馈「点开关没变化」「默认地址和模型名没了」，排查为预览页面造成的假象：`file://` 静态快照不运行脚本，本地 HTTP 预览没有扩展 API、读不到配置。注入真实 `ai-pipeline.js` 模拟读取配置后，默认值正常填入，开关正常展开图片组。
- 需要用户在浏览器里手动验证：
  1. 重新加载扩展后打开设置页，默认是一张「模型」卡、只显示一组字段，填 DeepSeek Key 点「测试模型」应显示「文字与图片均可用」。
  2. 把模型名改成只支持文字的模型再测，应提示图片识别失败并出现「改为文字与图片分开配置 →」；点击后图片组展开并预填。
  3. 分开模式下图片 Key 留空、两边同为 `api.deepseek.com` 时，图片帖概括应正常识图。
  4. 已保存过分开配置的浏览器，打开设置页应直接是分开状态。

## 遗留问题

- 图片测试靠回答里出现「红 / red」判断，个别模型若用其他说法（如「赤色」「#DC1E1E」）会被误判为不支持；出现时再放宽判断。已记入 backlog。

## 审核备注（仅当新增权限或数据流时）

本版本未新增权限。设置页的「测试模型」除原有的文字连通测试外，会向用户自己填写的模型 API 额外发送一张扩展内置的 32×32 纯色测试图片，用于确认模型是否支持图片输入；该图片不含任何用户或帖文数据，只在用户点击测试按钮时发送。文字概括与图片识别默认共用用户配置的同一个模型接口，用户也可分开配置；数据流向与此前一致，仍只发往用户自行配置的 HTTPS 模型接口。
