- 日期：2026-11-15
- 版本：manifest / package.json 均为 0.16.5
- 提交：见本次提交
- 委托：用户给第二条帖文（北京某高校公费医疗报销比例低，短链 `xhslink.cn/o/<短码>`），请实现方试能否概括出高校名称；看到初测结果后同意「调到正文与标题一致」。
- 关闭的 backlog 条目：无

## 排查

- 内置浏览器打开帖文（未登录，只显示前 10 条评论；扩展登录后可读 50 条），按 `content-script.js` 选择器取评论与发帖人回复。线索：发帖人答「公立呀！还是医学院」，被问「良乡校区吗」答「在和平街」，被问「北中医吗？」答「恨」。和平街、良乡正是北京中医药大学的两个校区。
- v0.16.4 规则下 5/5 标题写出北京中医药大学，但正文写「发帖人未明确确认」、观点区写「部分网民猜测为北中医」，与标题矛盾。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `prompts.js` | `SUBJECT_RULE`：①「足以认定」给出标准——发帖人透露的校区、学校类型等指向唯一主体，或与网民点名的主体吻合且发帖人没有否认；② 依据写法分开：发帖人确认的写「发帖人在评论区确认为……」，线索认定的写「据发帖人所述……可认定为……」且不能写成发帖人确认；不引用追问原文、不复述推断、不写「未明确确认」。③ 「已认定的不再单列猜测」从总规则移到 `TEXT_SYSTEM`、`MERGE_SYSTEM` 的 opinion_points 字段规则里（放在总规则时模型基本不听）。 |
| `tests/prompt-overrides.test.cjs` | 新增三项断言：认定标准、线索认定不写成确认、观点区不重复已认定猜测（单帖与合并都查）。 |
| `tests/service-worker.test.cjs` | 版本断言升到 0.16.5。 |
| `README.md` | 功能说明同步认定标准。 |

## 实测与验证

- `npm run check`：通过。
- DeepSeek（deepseek-chat，temperature 0.2）用还原证据迭代了四轮，最终版：
  - 公费医疗帖：8/8 标题写北京中医药大学，正文均为「据发帖人所述……可认定」，无误写「发帖人确认」；3/8 观点区仍有「部分网民猜测为北京中医药大学，称该校比例确实偏低」——这条同时带有真实观点，暂不处理。
  - 洗澡水帖（有发帖人「1」回复）：4/4 标题写北京工商大学，正文多为「发帖人在评论区回复网民追问时确认涉事学校为北京工商大学」，观点区不再重复猜测。
  - 洗澡水帖（去掉「1」回复，作为不足以认定的对照）：4/4 保留「某高校」，猜测写在观点区，新标准没有引起过度推断。
- 未覆盖：只用了未登录可见的 10 条评论；帖文 3 张图片未进证据（DeepSeek 不看图）；合并提示词只做了文本断言，没跑模型。需要用户重新加载扩展后实测。
