# v0.14.9 截图概括带上素材输入框里的链接

- 日期：2026-10-29
- 版本：manifest / package.json 均为 0.14.9
- 提交：分支 `fix/shot-summarize-missing-link` 的 HEAD（工作树 `.worktrees/fix-shot-link`，单提交）
- 委托：用户反馈「添加素材」里同时粘贴截图和短链后点「识别这张截图并概括」，结果却显示「原帖已删除，内容据用户上传截图整理」，粘贴的链接没有被带进结果；要求把链接修补进去。
- 关闭的 backlog 条目：无（本次为新问题，非既有条目）

## 改了什么

根因：`添加素材` 里链接输入框与截图暂存区是两条互不相通的链路。面板的 `summarizeScreenshotImages` / `addScreenshotImagesToBasket`（panel.js）发 `XHS_AI_SCREENSHOT_RECOGNIZE` / `XHS_AI_SCREENSHOT_ADD` 消息时只带图片，从不带链接；而后台 `recognizeScreenshots`（service-worker.js）早已支持可选 `sourceUrl` 字段并进 payload（v0.13.0 起），只是面板一直没传，成了死通道。

| 文件 | 改动 |
| --- | --- |
| `panel.js` | 新增 `screenshotLinkFromMaterialInput()`：用 `extractPostUrl` 从素材输入框提取链接，经 `validateScreenshotLink` 过滤（截图管线只覆盖小红书，微博链接不带入）。`commitStagedScreenshots` 提交时读取该链接，随两个截图消息传 `sourceUrl`（无链接时消息形状不变），成功后才清空输入框；加入清单的反馈文案追加「已带上输入框里的原帖链接」。 |
| `tests/panel.test.cjs` | 新增两段用例：输入框含 xhslink 短链时 `XHS_AI_SCREENSHOT_RECOGNIZE` 消息带 `sourceUrl` 且成功后输入框清空；输入框是微博链接时不带 `sourceUrl` 且输入框保留。既有「无链接 → sourceUrl undefined」断言保持不变。 |
| `tests/service-worker.test.cjs` | 版本号断言同步 0.14.9。 |
| `README.md` | 「截图识别」一节补充链接带入行为。 |
| `manifest.json` / `package.json` | 版本号 0.14.9。 |

后台零改动：`sourceUrl` 校验（`validateScreenshotSourceUrl`）与 payload 组装（`buildScreenshotPayload` 的 `context.sourceUrl`）沿用既有实现，短链保持原样不解析（与结果卡手动补链接的截图特判一致，删帖后短链也未必解析得动）。

## 实测与验证

- `npm run check`：通过（含新增用例与打包白名单防漏）。
- 需要用户在浏览器里手动验证：加载解包扩展后，在「添加素材」同时粘贴短链与截图 → 点「识别这张截图并概括」，确认结果来源行显示 `（小红书 <链接>）` 而非「原帖已删除」；再试「识别并加入清单」，确认清单条目带链接、反馈文案提示已带上链接。
