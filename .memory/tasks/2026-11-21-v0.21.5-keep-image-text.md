# v0.21.5 图里有字的配图不再被图片模型的取舍判断筛掉

- 日期：2026-11-21
- 版本：manifest / package.json 均为 0.21.5
- 提交：见本次提交
- 委托：用户反馈一条小红书帖（研一学生问 10 月款项是否补发）的配图明明写着「北理」，概括里却只写「某高校」，认不出北京理工大学；请诊断图片提取的问题并修复。用户提供了临时 DeepSeek Key 供实测（未写入仓库）。
- 关闭的 backlog 条目：无

## 原因

不是取图或识图失败，是程序在图片模型和文字模型之间把 OCR 文字扔掉了。

1. 帖文只有一张图：粉底大字卡片「北理补发的国补和校补啥时候到账银行卡呢」，帖文正文为空，标题「10月每月绑卡没收到，11月会补发吧？」。原图是 1080×1440 的 WebP，`image/webp`，不带 Referer 也能正常下载，图片服务器这一环没有问题。
2. 用插件自己的 `prompts.js` + `ai-pipeline.js`（Node 里加载，走 `prepareVision` / `summarize`）调 `deepseek-flash`：图片模型每次都把字认对了（`visible_text` 完整、`organizations: ["北理"]`），但 `summary_value` 时而给 `supporting`、时而给 `none`。这张卡片只是把标题再写一遍，容易被当成提示词里的「装饰封面」。
3. `ai-pipeline.js` 的 `selectVisionEvidence` 只放行 `essential` / `supporting`，判成 `none` 的整条连同 OCR 文字一起丢掉，文字模型拿不到「北理」，也拿不到「国补」「校补」。用户那次的结果里同样没有国补、校补，与 `imagesSelected: 0` 一致。
4. 这与决策日志「图片识别与文字概括分开调用」相冲突：决定写的是「图片模型只负责如实描述和 OCR；内容是否有增量、是否写进概括，由文字模型判断」，代码却让图片模型的取舍一票否决。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `ai-pipeline.js` | `selectVisionEvidence`：`essential` / `supporting` 照旧放行；判成 `none` 但 `visible_text` 非空的也放行（`normalizeVisionItem` 对 `none` 已清空 `factual_description`，只带 OCR 文字）。无字的 `none` 图仍筛掉，避免自拍、风景的画面描述进证据。 |
| `tests/service-worker.test.cjs` | 新用例：复述标题的文字卡片（`none` + 有字）保留、只有空白的 `none` 图筛掉，`buildEvidence` 的 `imageEvidence` 里有卡片原文。版本断言改为 0.21.5。 |
| `README.md` | 功能列表注明图里有字的配图一律交给文字模型取舍。 |
| `manifest.json` / `package.json` | 版本 0.21.5。 |

提示词未改。

## 实测与验证

- `npm run check`：通过。
- 变异验证：把 `selectVisionEvidence` 改回只放行 `essential` / `supporting`，新用例按预期失败；恢复后通过。
- DeepSeek 实测（`deepseek-flash`，文字与图片共用，评论按页面前 7 条一级评论及回复手工构造）：
  - 把图片识别结果固定为 `none`（复现失败那一次）只调文字模型：修复前标题为「网民反映每月打入银行卡的款项10月未到账」，`imagesSelected: 0`；修复后 3/3 次标题写出「北京理工大学」，正文带出国补、校补。
  - 全流程（真实取图、图片模型、文字模型）修复后 4/4 次标题写出「北京理工大学」。
- 需要用户在浏览器里验证：重新加载扩展后对这条帖文点「重新生成」。重新生成复用图片识别缓存，缓存里那次如果判了 `none`，也会因为本次改动被放行；文字缓存键含证据，证据变了会重新调文字模型。预期标题出现「北京理工大学」。

## 遗留问题

- 新增 backlog「文字模型偶尔把配图文字原样引用」：修复后 7 次实测中有 2 次正文写成「帖文所附文字提出“北理补发的……”」「帖中文字还询问……」，把图片原文照搬，或点明信息来自配图。写作提示词已要求不写「配图为……」，这是另一处措辞问题，本次不改提示词。
